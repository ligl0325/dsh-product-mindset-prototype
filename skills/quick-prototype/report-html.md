# HTML 报告模式

本模式把已形成的研究、分析或项目材料组织成可阅读、可打印的 HTML 报告。它负责报告的信息层级、视觉呈现和页面实现，不代替调研、数据分析或事实核验。

## 何时使用

- 用户要求 HTML 报告、网页报告或可打印的报告页面。
- 用户已提供研究结果、结论、数据或现有文档，要求整理成报告。
- 用户同时要求调研和 HTML 报告：先完成适用的研究工作流，再使用本模式呈现结果；不要把“网页做出来了”说成“研究已验证”。

若用户只要 Word、PPT 或纯文本报告，不要把内容强行做成 HTML 原型。

## 组织内容

先明确报告要回答的问题、读者和阅读后的决策。根据材料选择必要章节，不强行套满目录。面向决策的报告通常可以依次呈现：

1. 标题、对象、时间范围和数据口径。
2. 结论摘要：先回答核心问题，给出最重要的发现。
3. 关键发现及其证据、分析和限制。
4. 对产品、业务或项目的影响。
5. 建议行动、优先级和待验证事项。
6. 来源、方法和口径说明。

清楚区分来源事实、分析判断、建议和待验证假设。保留材料中的范围、日期、单位、样本量和口径；发现矛盾时标明，不擅自合并。缺少证据的结论应标注“待验证”或说明缺少什么，不用看似精确的数字填空。来源应贴近对应结论，链接或标注到具体文档、页面或数据表。

## 页面设计

- 首屏让读者看懂报告主题、结论和范围；目录较长时提供锚点导航。
- 按结论的重要性安排版面。摘要、证据、分析和行动项有清楚层级，避免连续堆砌卡片、过长段落或无信息量的装饰。
- 图表只在数据结构和比较关系支持时使用；图表注明时间、单位、样本或统计口径。概念关系用流程图或关系图，不用伪数据图表。
- 正文使用适合连续阅读的行宽和字号。自然段应按语义换行，避免把完整句子拆成多行展示；窄屏时允许自然折行。
- 页面适配桌面和手机；提供打印样式，打印时隐藏导航和无关控件，避免标题、图表和说明被不合理拆页。
- 优先使用单文件、内嵌 CSS 的 HTML，不依赖外部 CDN；若依赖外部资源，说明离线打开时的限制。

## 交付检查

检查章节导航、锚点、链接、图表注释、来源标记和打印布局。若具备浏览器检查能力，再查看桌面与窄屏布局；只描述实际检查过的结果，不把代码生成等同于浏览器验证。
