# 快速原型生成

为产品经理和设计师快速生成单文件可交互 HTML 原型。覆盖 Web 后台、H5 移动端、原生 APP（iOS/Android）、PC 桌面端、嵌入式/穿戴/小屏、会议一体机六种设备形态，也可将已有分析结论和证据整理成 HTML 报告。

## 输出类型分流

- **交互原型**：用户要页面、交互、流程演示或设备界面时，执行下方原型流程，并按需读取对应设备模板。
- **HTML 报告**：用户要把研究结果、分析结论或已有材料交付为网页报告时，读取 [report-html.md](report-html.md)。本模式负责信息组织和页面呈现，不自行补造研究过程、数据或结论。
- **研究 + HTML 报告**：先用用户提供的材料或适用的研究工作流建立内容与证据，再按报告模式呈现；研究产出和页面交互分别表达。

## 原型生成流程（仅原型模式）

1. **确定设备形态** — 根据用户描述判断，或询问用户
2. **设计解读** — 分析受众、调性、约束，输出一句话"设计解读"
3. **识别业务领域** — 分析产品所属行业，匹配设计规则（参考 [design-rules.md](design-rules.md)）
4. **设定三拨盘** — 根据解读设定布局变体/动效强度/信息密度
5. **生成设计系统** — 根据领域推理：风格 → 配色 → 字体 → 反模式
6. **读取对应模板** — 参考下方模板文件获取完整 HTML 骨架
7. **搭建页面** — 根据业务需求组合组件，应用设计系统
8. **填充数据** — 用贴合业务的真实数据替换占位内容
9. **反AI审美检查** — 逐条过反 AI 审美红线，消除"AI味"
10. **质量检查** — 按文末检查清单 + 行业反模式验证

## 确定设备形态

| 形态 | 典型屏幕 | 关键词触发 |
|------|---------|-----------|
| Web 后台 | 1280px+ | 后台管理、CRM、ERP、OA、Dashboard |
| H5 移动端 | 375-414px | 手机网页、微信内页、H5、WebView 页面 |
| 原生 APP | 375-430px (iOS/Android) | 明确要求原生 APP、iOS/Android 客户端或平台原生控件 |
| PC 桌面端 | 1280px+ | 桌面客户端、桌面软件、Windows 应用、监控台 |
| 嵌入式/穿戴/小屏 | 240×240 ~ 800×480 | 服务器面板、嵌入式、手表、手环、小屏、工业屏、平板终端 |
| 会议一体机 | 3840×2160 (100寸) | 会议大屏、一体机、投屏、会议室电视、大屏看板、电子白板 |

优先依据用户描述和上下文推断。若用户只说“做个原型”且没有形态线索，默认单页响应式 Web 原型，并在交付时说明这个假设；如果嵌入方式、固定屏幕尺寸或原生平台要求会明显改变结构且无法判断，只问一个关键问题。

## 设计解读 (Design Read)

在生成任何代码之前，先"读懂房间"。大多数 AI 生成的界面质量差，是因为跳过了理解直接套模板。

### 解读信号

1. **页面类型** — 看板/列表/详情/表单/大屏/欢迎页
2. **受众** — 给谁看的？一线员工/管理层/客户/访客/运维工程师
3. **调性词** — 用户说了什么？"专业""简洁""科技感""高级""清爽""稳重"
4. **静默约束** — 无障碍优先？受监管行业？信创环境？暗光场景？这些约束**覆盖**审美偏好
5. **已有品牌资产** — 已有 logo/主色/字体？红头文件规范？VI 手册？

### 一句话设计解读

在生成前，先内部输出一句（不展示给用户，用于指导生成）：

> *"解读为：[设备形态] 的 [页面类型]，面向 [受众]，[调性] 风格，偏向 [风格方向]。"*

示例：
- *"解读为：Web 后台的 CRM 客户管理看板，面向一线销售，专业简洁风格，偏向极简瑞士风+专业蓝。"*
- *"解读为：嵌入式 480×320 的服务器监控面板，面向运维工程师，科技硬核风格，偏向 HUD 深色+状态灯。"*
- *"解读为：会议一体机的欢迎签到屏，面向参会高管，高端大气风格，偏向深色+大数字+头像网格。"*

如果无法自信解读，**只问一个问题**（不要多问）：*"这个原型是给谁看的，希望什么感觉？"*

## 三拨盘 (Three Dials)

设定三个参数驱动所有布局和动效决策：

这些数值只是内部启发式，不是客观评分；除非用户要求解释设计取舍，否则不必展示数值，也不要为了凑分数改变布局。

| 拨盘 | 范围 | 含义 | 原型默认值 |
|------|------|------|-----------|
| **布局变体** LAYOUT_VARIANCE | 1-10 | 1=完全对称 10=创意不对称 | **4** (原型偏规矩) |
| **动效强度** MOTION_INTENSITY | 1-10 | 1=静态 10=电影级 | **3** (原型克制) |
| **信息密度** VISUAL_DENSITY | 1-10 | 1=画廊留白 10=驾驶舱密集 | **6** (原型偏密集) |

### 拨盘推理（根据设计解读自动设定）

| 信号 | 布局变体 | 动效 | 密度 |
|------|---------|------|------|
| "简洁/清爽/极简" | 3-4 | 2-3 | 4-5 |
| "专业/稳重/企业级" | 4-5 | 2-3 | 5-6 |
| "科技感/高级/酷炫" | 5-6 | 4-5 | 5-6 |
| "数据密集/监控/运维" | 3-4 | 2-3 | 7-8 |
| "大屏展示/会议/看板" | 3-4 | 3-4 | 5-6 |
| "嵌入式/工业/小屏" | 2-3 | 1-2 | 6-7 |

### 拨盘如何驱动输出

- **布局变体 ≤ 4**：对称网格、居中布局、标准侧栏导航
- **布局变体 ≥ 7**：可尝试不对称卡片、留白区域、创意排版
- **动效 ≤ 3**：仅页面切换 fade、按钮 :active 反馈、toast 出入
- **动效 ≥ 6**：可加数字滚动、进度条动画、数据刷新渐入
- **密度 ≤ 4**：大留白、少元素、每个模块只展示一个核心信息
- **密度 ≥ 7**：紧凑网格、多维数据同屏、信息模块密集排列

## 设计系统推理

根据业务领域自动生成匹配的设计方案。推理流程：

```
用户请求 → 识别业务领域 → 匹配行业规则 → 选择风格+配色+字体 → 过滤反模式 → 输出设计系统
```

### 业务领域快速匹配

| 领域 | 关键词 | 推荐风格 | 配色氛围 | 必须避免 |
|------|--------|---------|---------|---------|
| 企业管理/SaaS | CRM、ERP、OA、后台 | 极简瑞士风、柔和UI | 专业蓝/灰、可信赖感 | 花哨渐变、霓虹色、卡通元素 |
| 金融/财务 | 银行、支付、财务、报表 | 极简主义、密度数据 | 深蓝/墨绿、稳重保守 | 亮粉/亮紫、过度动效、圆角过大 |
| 医疗健康 | 医院、诊所、药品、监护 | 无障碍设计、包容性 | 青绿/白、洁净感 | 深色模式(除非监护屏)、红色大面积 |
| 工业/IoT | 工厂、嵌入式、传感器 | HUD科幻、深色OLED | 高对比深色、状态色醒目 | 浅色背景(车间看不清)、精细渐变 |
| 教育/培训 | 学校、课程、考试 | 粘土拟态、活力块状 | 明亮多彩、友好活泼 | 深色压抑、过于严肃 |
| 电商/零售 | 商城、订单、商品 | 扁平设计、微交互 | 品牌色突出、CTA醒目 | 信息过载、按钮不够醒目 |
| 会议/协作 | 大屏、会议、签到 | 数据密度看板、极简 | 深色高级感、主色高亮 | 小字号(远距不可读)、密集元素 |
| 监控/运维 | 服务器、告警、网络 | 实时监控、HUD科幻 | 深色+状态色(绿黄红) | 浅色(机房刺眼)、动效过多 |

### 风格选择优先级

根据**设备形态 × 业务领域**交叉决定：

行业配色和风格是起点，不是硬性规则。用户提供的品牌资产、真实使用环境、无障碍要求和明确偏好优先。

- **Web 后台 + 企业管理** → 极简瑞士风/柔和 UI，主色蓝系，间距宽松
- **Web 后台 + 监控运维** → 实时数据密度看板，深色主题，紧凑布局
- **H5 + 电商** → 微交互、扁平设计，CTA 按钮突出
- **H5 + 医疗** → 无障碍设计，大字号，高对比度
- **APP + 电商/零售** → iOS HIG / Material Design 原生风格，品牌色突出，Tab 导航
- **APP + 金融** → 保守稳重，深蓝/墨绿，Material 风格数据密度适中
- **APP + 社交/通讯** → iOS 原生分组列表或 Material 卡片，主色微信绿或品牌色
- **PC 桌面 + 工业** → HUD/科幻 FUI，深色高对比
- **嵌入式 + 工业/IoT** → 深色 OLED 风格，极大数字，极简信息
- **嵌入式 + 医疗** → 浅色洁净主题，柔和绿色系
- **会议大屏 + 企业管理** → 高管仪表板风格，大网格，远距可读

### 反模式红线（任何领域都不可触碰）

- 不用 `alert()` 代替 toast
- 不用 "测试" "test" 等占位文字
- 不用 neon/霓虹色（`#ff00ff` `#00ffff`）除非赛博朋克主题
- 不在金融/医疗/企业场景用卡通 emoji 做图标
- 不在需要远距阅读的场景用小于 20px 的字号
- 不在深色工业场景用精细阴影/渐变（低端屏无法渲染）
- hover 状态过渡时间不低于 150ms、不超过 300ms
- 可交互元素必须有 cursor:pointer 或视觉反馈

### 反 AI 审美红线（消除"AI味"）

以下是 AI 生成界面的高频俗套，生成时必须主动规避：

**配色俗套**：
- 默认紫蓝渐变（`#667eea → #764ba2`）—— AI 最爱，一看就假
- 全站只用一种灰（zinc/slate/stone 混用）—— 锁定一种灰底贯穿全页
- 暖米色+黄铜色+深棕色—— "高端消费品牌"的 AI 默认配色，已烂大街

**布局俗套**：
- 每个卡片区域都套一层白色圆角阴影卡片 —— 不是所有东西都需要卡片
- 三列等宽 feature cards —— 最典型的 AI 布局，用 2+3、bento 网格、或不对称替代
- 每个 section 上方都加一行大写小字标签（eyebrow）—— 最多每 3 个区块用 1 个

**交互俗套**：
- 所有按钮/卡片都加 hover:scale(1.05) —— 克制使用，只在核心 CTA 上用
- 每个数据变化都加 infinite-loop 动画 —— 信息类区块保持静态
- 空状态直接留白 —— 必须有友好的空状态提示（图标+文字）

**内容俗套**：
- 虚假精确数字（`92%`、`4.1×`、`48k`）没有来源标注 —— 原型数据标注为示例
- 每个区块都是"标题+3行描述+图标"的重复节奏 —— 变化布局家族
- 所有人名用"张三/李四" —— 用更自然的中文名（张明远、李思琪、王建国）

**完整的行业设计规则、67种风格索引、配色方案和反模式清单**：参考 [design-rules.md](design-rules.md)

## 通用规则

### 文件约束

- **单文件**：所有 HTML + CSS + JS 在一个 .html 文件中
- **零依赖**：不引用外部 CDN（除非用户明确要求图表库等）
- **编码**：UTF-8，meta charset 声明
- 双击即可在浏览器中打开运行

### 字体

```css
font-family: -apple-system, "PingFang SC", "Microsoft YaHei", sans-serif;
/* 数字和数据用等宽字体区分 */
font-family: "SF Mono", "Cascadia Code", Consolas, monospace;
```

### 配色体系

每个原型需确定一个主色，并搭配语义色：

- 主色：用于导航、按钮、高亮（用户指定，默认 `#2563eb` 蓝色）
- 成功 `#16a34a`、警告 `#d97706`、危险 `#dc2626`、信息 `#2563eb`
- 中性灰：主文字 `#333`、次文字 `#666`、辅助 `#999`、分隔线 `#eee`

### 数据

- 优先使用用户或来源材料提供的数据，不用"测试123"
- 缺少真实数据时使用合理的虚构演示数据，并标注“示例数据”或“演示数据”；不得把虚构数据、公司、人名或业绩描述成真实
- 数字带单位（¥、%、个、万）；没有来源的数字不能写成事实

### 交互

- 页面切换：JS 控制 `.active` 类切换显示/隐藏
- 弹窗：overlay + box，点击遮罩层关闭
- 按钮反馈：优先 toast 提示（自动消失），禁用 `alert()`
- 表单：基础非空校验 + 错误提示文字
- Tab 切换：JS 控制内容区显隐
- 按组件和场景补充有意义的状态，不强制每个控件都具备默认、hover、disabled、loading、error、empty 六种状态

## Web 后台设计规则

**布局**：左侧固定导航栏 (200-240px) + 右侧内容区，导航深色背景 + 白色文字。

**页面类型与设计要点**：

- **看板页**：指标卡片网格 (3-4列) + 数据表格/图表区 + 待办列表
- **列表页**：顶部筛选栏 + 新增按钮，表格含斑马纹和 hover 高亮，底部分页
- **详情页**：面包屑返回 + 键值对网格 (2列) + 状态标签 + 操作按钮组
- **表单页**：标签 (100px) + 输入框 (320px)，分组用卡片包裹，底部提交/取消

**指标卡片结构**：大数字 (28-36px bold 主色) + 标签 (13px 灰色) + 趋势 (绿↑红↓) + 浅色背景。

**字号**：页面标题 20-22px、卡片标题 15px、正文/表格 13-14px、辅助 12px。

**完整模板与组件**：参考 [templates-web.md](templates-web.md)

## H5 移动端设计规则

**布局**：底部固定 Tab 栏 + 顶部状态栏 (可选) + 内容区。viewport 设为 `width=device-width,initial-scale=1,maximum-scale=1,user-scalable=no`。

**触屏约束**：所有可点击元素 min-height 44px，按钮建议 48px。无 hover 效果，用 `:active` 反馈。

**页面类型**：

- **卡片列表页**：全宽卡片垂直排列，卡片内：头像/图标 + 标题 + 描述 + 右侧箭头
- **详情页**：关键信息置顶 (大图标/头像)，下方分区信息，底部固定操作栏
- **表单页**：单列布局，输入框占满宽度，标签在上方，底部固定提交按钮
- **消息页**：聊天气泡，左侧对方 (灰底) 右侧自己 (主色底白字)，时间居中分隔

**字号**：标题 17-20px、正文 14-15px、辅助 12px。

**完整模板与组件**：参考 [templates-h5.md](templates-h5.md)

## PC 桌面端设计规则

**布局**：顶部菜单栏 + 工具栏 (可选) + 三栏区域（左侧面板 180-260px + 中央工作区自适应 + 右侧属性面板 200-280px 可选）。

**设计特征**：

- 模拟窗口标题栏 (含关闭/最大化/最小化按钮)
- 紧凑字体和间距：正文 13px，最大化利用屏幕空间
- 面板间用 1px 边框或 4px 分隔条
- 支持多标签页工作区
- 右键菜单用 div 模拟，点击空白处关闭

**布局类型**：

- **导航树 + 工作区**：适合配置管理、文件浏览器、设置页
- **三栏布局**：适合编辑器、IDE 风格工具、监控台
- **多标签页 + 工作区**：适合多文档/多任务界面

**键盘快捷键**：通过 JS 监听 Ctrl+S/Z/N、Delete、Ctrl+F 等，显示在菜单项旁。

**完整模板与组件**：参考 [templates-desktop.md](templates-desktop.md)

## 嵌入式/穿戴/小屏设计规则

**核心原则**：屏幕极小、深色主题、极简交互、每屏只做一件事。

| 设备 | 分辨率参考 | 主交互 |
|------|-----------|--------|
| 手表 | 240×240 圆屏 | 触摸滑动 |
| 手环 | 128×240 窄长屏 | 触摸/按键 |
| 嵌入式小屏 | 320×240 ~ 480×320 | 触摸/物理按键 |
| 服务器外带屏 | 480×320 ~ 800×480 | 触摸 |
| 安卓平板终端 | 800×480 ~ 1024×768 | 触摸 |

**设计约束**：

- 优先深色背景 (`#0a0a0a`/`#1a1a2e`)，高亮文字
- 医疗/洁净环境可用浅色主题
- 触摸目标 ≥ 48px，物理按键设备在底部显示对应软键标签
- 数字放大 (36-72px)，状态用色块表示
- 极简信息密度，动画从简（低端硬件）

**布局类型**：

- **圆形表盘**：中心大数字 + 环形小指标 + 底部日期
- **窄长手环**：纵向堆叠，上下滑动切换屏
- **嵌入式小屏**：顶部状态栏 + 中央数据区 + 底部软键
- **带按键设备**：内容与物理按键映射
- **平板终端**：网格仪表盘或列表操作界面

**状态色**：正常 `#4ade80`、警告 `#fbbf24`、故障 `#f87171`、信息 `#60a5fa`、离线 `#6b7280`。

**完整模板与组件**：参考 [templates-embedded.md](templates-embedded.md)

## 会议一体机设计规则

**场景特征**：100寸大屏 (3840×2160 或 1920×1080)、多人从 2-5 米距离观看、支持多点触控 (20+触点)、通常 Android 或 Windows 系统。

**核心原则**：远距离可读、多人同时观看、触控操作简单直接、信息密度低但视觉冲击力强。

**布局规则**：

- 全屏无边框设计，内容占满整个可视区域
- 顶部标题栏 (60-80px)：会议主题/系统名称 + 时间 + 状态
- 内容区采用大网格布局 (2×2、3×2、4×2)，每个格子是一个独立信息模块
- 底部操作栏 (可选, 80px)：常用操作按钮，方便站立触控
- 支持分屏：左右两栏或三栏并排（如左侧议程 + 中间看板 + 右侧计时器）

**字号与触控**：

- 标题 48-72px、正文 28-36px、辅助 20-24px
- 触摸目标 ≥ 80×80px（站立触控，手指距离远精度低）
- 按钮文字 ≥ 24px，间距宽松
- 避免密集小元素，每个信息模块聚焦一个核心内容

**页面类型**：

- **数据看板**：大指标卡片网格 + 趋势图 + 实时数据流
- **会议议程**：时间轴布局，当前议题高亮，已完成打勾
- **任务看板**：大卡片网格，每人一栏或每状态一栏
- **倒计时/计时器**：超大数字居中 + 进度环 + 阶段标签
- **欢迎屏/签到屏**：全屏背景 + 居中大标题 + 参会人头像网格

**视觉特征**：

- 高对比度配色，深色背景优先（会议室光线可控但需醒目）
- 信息模块间用明显分隔（间距 16-24px 或 2px 亮色分隔线）
- 数字超大展示 (48-96px)，关键数据用主色高亮
- 动画简洁大方，适合大屏幕展示（数据刷新渐入、数字滚动）

**完整模板与组件**：参考 [templates-conference.md](templates-conference.md)

## 原生 APP 设计规则

**平台差异**：iOS 遵循 Apple HIG，Android 遵循 Material Design。原型通过 `:root` 与 `:root.android` 切换平台配色和组件风格，默认 iOS。

**布局**：

- **iOS**：顶部 Navigation Bar (44px) + 内容区 + 底部 Tab Bar (49px)。支持 Large Title (大标题导航栏, 96px 起始, 滚动收缩为 44px)
- **Android**：顶部 App Bar (56px) + 内容区 + 底部 Bottom Navigation (56px)。可选 FAB 悬浮操作按钮 (56px 圆形)
- 全屏模拟时需包含状态栏 (iOS 44px / Android 24px) 和底部安全区 (Home Indicator 34px / Android 导航条)

**安全区 (Safe Area)**：

- iOS 刘海屏顶部预留 44px、底部 Home Indicator 预留 34px
- 使用 `env(safe-area-inset-top)` 和 `env(safe-area-inset-bottom)` 作为参考值
- 内容区 padding-bottom 须包含安全区高度，避免被 Home Indicator 遮挡

**触屏约束**：

- iOS 最小触摸目标 44×44px，Android 最小 48×48dp
- 无 hover 效果，用 `:active` 提供按压反馈（背景变暗或透明度变化）
- 列表项建议 min-height 48px，按钮建议 44-48px 高度
- 滑动手势：左右滑动删除/操作（用 JS 模拟 touchstart/touchmove）

**iOS 专属组件**：

- Grouped List（设置页风格分组列表，圆角卡片内嵌列表项）
- Segmented Control（分段选择器，2-5个选项）
- Toggle Switch（iOS 风格开关，51×31px）
- Action Sheet（底部弹出操作面板，取消按钮独立分组）
- HUD Toast（毛玻璃背景居中提示，自动消失）

**Android 专属组件**：

- Material List Item（带图标/头像的列表项，左侧 40px 图标区）
- FAB（悬浮操作按钮，右下角 56px 圆形，带阴影）
- Bottom Sheet（底部抽屉面板，可拖拽展开）
- Snackbar（底部消息条，可含操作按钮）

**页面类型**：

- **列表页**：导航标题 + 搜索栏 (可选) + 分组列表/平铺列表 + 底部 Tab
- **详情页**：大标题/封面图 + 信息分区 + 底部固定操作栏
- **表单页**：分组列表风格输入 (iOS) 或 Material 输入框 (Android)，标签左/上对齐
- **个人中心**：顶部头像卡片 + 分组菜单列表 + 设置入口
- **消息/聊天**：气泡对话 + 底部输入栏 + 键盘区域预留

**字号**：

- iOS：大标题 34px、导航标题 17px semibold、正文 17px、辅助 13px、Tab 标签 10px
- Android：App Bar 标题 20px medium、正文 16px、辅助 12px、Bottom Nav 标签 12px

**配色预设**：iOS 蓝 `#007aff`、Material 蓝 `#1a73e8`、微信绿 `#07c160`、支付宝蓝 `#1677ff`、抖音深色 `#fe2c55`、美团黄 `#ffc300`。根据业务领域选择。

**完整模板与组件**：参考 [templates-app.md](templates-app.md)

## 质量检查清单

### 基础检查

- [ ] 单文件 HTML，`<meta charset="UTF-8">`
- [ ] 双击浏览器打开正常显示，无乱码
- [ ] 导航/Tab 切换页面正常
- [ ] 设备形态布局正确（侧栏/底栏/三栏/小屏/大屏看板/APP导航+Tab）
- [ ] APP 形态：安全区已预留（状态栏+刘海/Home Indicator），触摸目标 ≥ 44px(iOS) 或 48px(Android)
- [ ] 无 `alert()`，用 toast 替代
- [ ] 使用来源明确的数据；演示数据已明确标注，不伪装成真实数据
- [ ] 中文字体栈已设置
- [ ] H5 元素可点击区域 ≥ 44px，嵌入式 ≥ 48px，会议大屏 ≥ 80px

### 设计系统检查

- [ ] 配色方案与业务领域匹配（参考 design-rules.md）
- [ ] 未触犯行业反模式红线
- [ ] 交互元素有 cursor:pointer 或 :active 视觉反馈
- [ ] hover/过渡动画 150-300ms，不过快也不过慢
- [ ] 金融/企业场景：无霓虹色、无卡通 emoji 图标
- [ ] 医疗场景：无大面积深色模式（监护屏除外）、红色仅用于告警
- [ ] 工业/嵌入式：高对比度，无精细渐变（低端屏无法渲染）
- [ ] 会议大屏：最小字号 ≥ 20px，信息密度低，远距可读
- [ ] 深色主题仅用于适合的场景（嵌入式/监控/会议/工业）
- [ ] 至少检查一条核心操作路径及其成功反馈；只验证实际检查过的交互

### 反 AI 审美检查（消除"AI味"）

- [ ] 无默认紫蓝渐变（`#667eea → #764ba2`）
- [ ] 不是所有区域都套了白色圆角卡片（留白/分隔线/负空间也算布局）
- [ ] eyebrow 小标签数量 ≤ ceil(区块数/3)
- [ ] 按钮文字对比度 ≥ 4.5:1（白底白字、透明按钮无边框 → 禁止）
- [ ] 空列表/空表格有友好的空状态提示
- [ ] 表单必填字段有视觉标记（红色*或底色区分）
- [ ] 布局有节奏变化（不是每个 section 都"标题+3列卡片"重复）
- [ ] 阴影带色调（不是纯黑 `rgba(0,0,0,x)`，而是偏向背景色相）
- [ ] 圆角统一（全页只用一套 radius 尺度：0/8/12/16 选一贯穿）

### 一致性锁检查

- [ ] 主题锁定：全页同 light 或同 dark，不在中间翻转
- [ ] 配色锁定：一个主色贯穿全页，不在 footer 突然换色调
- [ ] 灰底锁定：zinc/slate/stone 只选一种，全页统一
- [ ] 圆角锁定：选定 radius 尺度后全页一致（按钮/卡片/输入框/弹窗）

## 常见变体

- **只需单页**：省略导航框架，直接输出页面内容
- **多配色方案**：替换主色即可，其余结构不变
- **交互原型**：用 JS 模拟数据增删改查和页面状态变化
- **对比方案**：同一文件内用 Tab 切换展示不同设计方案
- **含图表**：允许引入 ECharts/Chart.js CDN，仅用于图表区域
