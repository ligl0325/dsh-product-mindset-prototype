# 多方角色评审工作流

## 何时使用

PRD、方案、版本范围、商业策略或重大变更进入下一阶段前。

## 投票角色

| 角色 | 一票关注点 | 可否否决 |
|---|---|---|
| PM | 用户价值、范围、可用性 | 普通反对票 |
| 技术 | 可行性、架构、工期、运维 | 普通反对票；不可交付可阻断 |
| 市场 | 可销售性、竞争差异、传播 | 普通反对票 |
| 法务 | 合规、隐私、知识产权、合同 | 红线问题一票否决 |
| 财务 | ROI、现金流、毛利、交付成本 | 预算超线可阻断 |
| 创始人/业务负责人 | 战略一致性、长期壁垒 | 普通反对票 |
| PMO | 汇总证据、管理CR、最终裁决 | 不额外投票，只裁决 |

## 评审规则

1. 六个角色独立阅读，各投：✅通过 / ⚠️有条件通过 / ❌反对。
2. 每张反对票必须写证据、影响和替代方案。
3. 法务红线直接退回；预算超线必须重算范围。
4. PMO按证据裁决，不得用“领导意见”覆盖未解决问题。
5. 所有CR全局编号，状态为open→in_review→approved/rejected→merged。
6. 没有落地证明的CR视为未完成。

## PMO裁决规则

- 全部通过：进入下一阶段。
- 无否决且最多2张条件票：有条件通过，必须设截止时间。
- 任一法务否决、预算阻断、技术不可交付：退回整改。
- 三张及以上反对票：重新定义范围，不允许靠PMO强推。
