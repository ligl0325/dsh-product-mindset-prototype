# 产品Brief工作流

## 何时使用

单个功能、方向或机会尚未进入正式立项，需要用最小成本判断“做、先验证、还是不做”。

## 输入门禁

目标用户、当前做法、痛点频率/损失、为什么现在做、最小验证条件。缺少其中三项以上时，不进入方案设计。

## 使用规范

- 先读“何时使用”和“输入门禁”，再执行步骤。
- 缺失关键输入时，只列信息缺口，不自行补造。
- 输出必须包含结论、边界、明确不做和可验证标准。


## 执行步骤

1. 具体到一个真实角色，不写“用户”。
2. 用频率×损失量化痛点。
3. 判断时间窗口：现在发生了什么变化。
4. 给出零开发或低成本验证方案。
5. 划清MVP与明确不做。
6. 最终只给一个结论：✅做 / ⚠️验证后做 / ❌不做。

## 方法正文

### 4.1 产品诊断五问

**什么时候用**：做一个新功能/新产品前、方向不确定时、评审前自检。

#### 五问逐层追问

```
第一问：这是给谁用的？
  不能答"用户"或"客户"。必须答到一个人。
  → "张三，35岁，一线销售，管40个项目，每天接15个询价电话。"
  追问：他是高频用户还是偶发用户？他有没有其他替代方案？

第二问：他有什么痛点？
  不能答"效率低"。必须量化。
  → "每天花30分钟写日报，占工作时间的6%。经常漏填导致被扣200元绩效。"
  追问：这个痛点每天发生几次？现在他怎么解决的？

第三问：为什么是现在做？
  不能答"因为重要"。必须回答什么变了。
  → "竞品上个月刚发布类似功能。公司Q2战略要求销售效率提升。"
  追问：三个月前为什么没做？三个月后做会怎样？

第四问：最小的验证方案是什么？
  不能答"上线了才知道"。必须给出验证方法。
  → "用一个Excel模板替代，让3个销售试用一周，看日报填写时间是否缩短。"
  追问：不需要做完整系统，怎么花最小成本验证需求？

第五问：明确不做什么？
  不能答"暂时不做"。必须划清边界。
  → "不做报表分析（V2.0做）、不做自动生成（V1.1做）、不做审批流（交给OA）。"
  追问：如果需求方说"顺便加上"，拒绝的理由是什么？
```

#### 产出物模板

```
# 产品 Brief：xxx

## 用户画像
[名字]，[年龄]，[角色]，[当前状态]，[核心痛点一句话]

## 痛点描述
[场景描述，3-5句话]

## MVP 范围
| 做 | 不做 |
|---|------|
| [功能A] | [功能B，V2.0] |
| [功能C] | [功能D，意义不明] |

## 验证方案
[最小成本验证方法，1句话]

## 决策
[建议做 / 建议验证后决定 / 不建议做]
```
