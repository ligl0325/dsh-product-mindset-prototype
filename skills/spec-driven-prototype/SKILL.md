# 规格驱动原型

## 这个技能解决什么

把一份**需求规格**变成一套**多页可运行的后台原型**，并且保证两件事：

1. **字段不会漂移** —— 原型的字段、枚举、必填、明细行**全部由规格生成**，不手写。规格改一次，重跑脚本，原型同步。
2. **字段跟来源系统逐字一致** —— 字段名、枚举取值、甚至错别字都照抄老系统界面，不"顺手修正"。

它针对的典型场景：**客户有旧系统（订单/合同/台账/审批类），要迁到新系统**。旧系统界面就是字段的事实来源；新系统可以重新设计信息架构，但字段必须对得上，否则上线对不上账。

> 单文件 HTML 原型不要用本技能，用 `quick-prototype`；只出需求表不出原型用 `requirement-analysis`；原型做好了要评审用 `product-prototype-review`。

## 十铁律（不可让步）

这十条是这类项目最容易翻车的地方。细则与反例见 [references/conventions.md](references/conventions.md)。

| # | 铁律 | 一句话理由 |
| --- | --- | --- |
| 1 | **规格是唯一事实源，原型字段不许手写** | 两套字段模型必然漂移；我们踩过「文档 750 字段、原型 15 字段」 |
| 2 | **改源不改产物** | 产物必须能由脚本重生成；直接改产物下次重跑就没了 |
| 3 | **一个菜单项 = 一类单据**（含明细表与报表视图） | 按「台账/处理/明细」三拆、按部门拆，都是把老系统的报表页当菜单 |
| 4 | **字段与来源系统逐字一致** | 含保留原系统错别字、并格拆开、去尾部冒号；不做"顺手修正" |
| 5 | **字段标来源三类** | 外部引用（只读带出）/ 本单录入 / 系统计算；用户要一眼看出哪些不用填 |
| 6 | **起单锚点按业务定，不照抄老系统** | 老系统以客户为中心，新系统可能以项目为中心 —— 这是业务决策不是界面问题 |
| 7 | **兜底入口必须留痕** | 允许不经外部系统直接建单，但原因必填 + 可事后补关联 + 列表可筛 |
| 8 | **原型不写业务规则** | 规则、口径、状态定义只写需求文档；原型只留操作提示、校验反馈、空态、实时计算结果、短指标标签 |
| 9 | **列表铺满 + 分页 + 列配置；详情是独立页面不是弹窗** | 弹窗装不下几十个字段，也没法被链接、被收藏 |
| 10 | **自检断言旧口径词为 0** | 口径改过一次以后，旧词会散落在文档和原型里；让脚本直接报错 |

## 五步工作流

```
① 抽字段   老系统界面 → 结构化字段表（位置/枚举/必填）
② 建规格   六表单一事实源（页面/字段/需求/权限/交互/字典）
③ 生成字段 规格 → 原型的字段定义（fieldSets / lineColumns）
④ 建原型   列表 / 详情 / 建单 三模板 + 四个通用组件
⑤ 验收     规格自检 + 原型审计 + 逐屏截图
```

每步的输入、动作、产出物与完成判据见 [references/workflow.md](references/workflow.md)。

## 开工前必须问清的四件事

这四件事问不清楚，后面一定会返工：

1. **菜单怎么分？** 是按单据类型分（本技能默认），还是按部门/角色分？
2. **起单锚点是什么？** 订单从哪来 —— 选外部对象（项目/客户/合同）带出，还是手工填？
3. **要不要兜底入口？** 允许不经外部系统直接建单吗？若允许，必须留痕。
4. **哪些字段是只读带出的？** 哪些本单必须录？哪些是系统算的？

## 怎么把脚本跑起来

`scripts/` 里的生成器需要一份配置（页面→来源系统单据的映射、来源三分类名单、业务分组、明细行列集等）。

```bash
# 1. 抽字段
python scripts/extract-legacy-fields.py --dir <老系统界面文本目录> --out legacy.json --report report.md

# 2. 生成原型字段（先复制示例配置再改）
cp templates/cfg.example.json cfg.json      # 改 pageSource / pageAlias / sourceRoles / blocks / lineSets
node scripts/gen-fields.mjs --spec spec.json --legacy legacy.json --out src/data --config cfg.json

# 3. 自检与审计
node scripts/check-spec.mjs --spec spec.json --banned banned.txt
node scripts/audit-prototype.mjs --src src

# 4. 截图
node scripts/shoot.mjs --url http://127.0.0.1:5180 --out shots --steps steps.json
```

详细的输入输出与完成判据见 [scripts/](scripts) 各文件头部注释，以及 [references/workflow.md](references/workflow.md)。

## 最容易犯的三个错

1. **先动手写页面，后补规格** —— 写完 6 个页面才发现字段名对不上，全部返工。**顺序不能反。**
2. **字段抽取用「字段名」去重** —— 同一个字段在「查询条件」和「表单」都出现，会被丢掉一次。**去重键必须是（字段名 + 位置）。**
3. **把老系统的值和提示语当成字段** —— 公司名、部门路径、括号里的填写说明都会被抽成字段，必须清掉。

完整陷阱清单（含 10 条真实踩坑与处置）见 [references/pitfalls.md](references/pitfalls.md)。
