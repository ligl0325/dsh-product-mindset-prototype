# 规格六表：结构、生成链与自检

> **解决什么问题**：原型与需求文档对不上，根因通常是「规格不是一张表」。这份文件定死六张表的列、用途、主键、生成链与自检项，让规格成为**唯一事实源**，所有产物可重生成。

六表的关系：**页面清单是骨架，字段清单挂在页面上，需求总表提供溯源，权限矩阵按页面给角色，交互与状态描述页面之间怎么走，数据字典管枚举取值。**

## 总览

| 表 | 用途 | 主键 | 关联 | 规模口径 |
| --- | --- | --- | --- | --- |
| 01 页面清单 | 定义菜单与页面（ID、路由、类型、优先级、菜单归属） | 页面ID | 其他五表都靠页面ID挂靠 | 行数 = 菜单项 + 操作页 + 无页面项 |
| 02 字段清单 | 每个页面的字段（控件、必填、来源、规则、显示位置） | （页面ID + 字段名 + 显示位置） | 页面ID → 页面清单 | 行数 = 各页字段数之和 |
| 03 需求总表 | 五级需求，逐条可溯源 | 序号 | 页面ID → 页面清单；来源ID → 外部材料 | 序号必须是 1..N 连续唯一 |
| 04 权限矩阵 | 页面 × 角色 的可访问级别 | 页面ID | 页面ID → 页面清单 | 行数 = 页面数；格子数 = 页面 × 角色 |
| 05 交互与状态 | 跳转 / 弹窗 / 批量 / 规则 / 四态 | 编号 | 对象里写页面名，解析回页面ID | 编号按类型分段（J/D/B/R…） |
| 06 数据字典 | 枚举与实体约束，取值来自来源系统 | （实体 + 字段） | 字段清单的枚举字段应指向这里 | 每条对应一个真实枚举 |

---

## 01 页面清单

**用途**：菜单结构、路由、页面类型的唯一定义。菜单怎么分（一个菜单项 = 一类单据）在这里落地。

| 列 | 说明 | 例（举例） |
| --- | --- | --- |
| 页面ID | 主键，全局唯一，形如 域前缀-序号 | PAGE_ID |
| 页面名 | 菜单显示名，也是需求/字段里的页面名 | 销售订单 |
| 路由 | 菜单项实际路径 | /orders |
| 类型 | 台账 / 详情 / 建单 / 看板 / 配置 | 台账 |
| 主角色 | 主要归属角色 | 商务 |
| 优先级 | P0 / P1 / P2 | P0 |
| 覆盖需求数 | 该页需求条数（由需求总表反算） | 30 |
| 路由模板 | 带参数的上下文路由 | /orders/:id |
| 菜单归属 | 属于哪个菜单分组；无菜单写「—」 | 订单管理 |

**主键与关联**：页面ID。字段清单、权限矩阵、需求总表都以页面ID 关联；路由模板里的参数名要和详情/操作页一致。

**生成链**：来源材料（菜单决议）→ 源 JSON（六表之一）→ 规格 JSON 的 pages 数组 → Excel 的「02_页面清单」sheet；菜单文件与路由文件再由规格 JSON 生成。

**自检清单**

- 页面ID 唯一；无重复、无空值。
- **菜单归属**与菜单文件里出现的分组完全一致（不多不少）。
- 每个「—」菜单归属的页面都要有明确的进入路径（从哪个页面的哪个动作进），否则就是死页面。
- 路由模板里的参数（:id 之类）有且只有一处。
- 覆盖需求数 = 需求总表里该页面ID 的行数（反算一致）。

## 02 字段清单

**用途**：字段的唯一事实源。原型里的字段、枚举、必填全都从这里生成，页面里不许再出现手写字段清单。

| 列 | 说明 | 例（举例） |
| --- | --- | --- |
| 页面ID | 外键 | PAGE_ID |
| 字段 | 字段名，**来源系统原文**（含错别字，去尾冒号、去星号） | 对比竟标价 |
| 控件 | 文本 / 下拉 / 日期 / 表格列 / 数值 | 下拉 |
| 必填 | 是 / 空 | 是 |
| 数据源 | 可追溯的出处：来源系统·页面名，或本单录入 / 系统计算 | 老系统·新方案销售订单 |
| 校验与规则 | 枚举写「枚举：值1,值2,...」；其它写校验口径 | 枚举：草稿,审核中,审核通过 |
| 显示规则 | **位置**（查询条件 / 列表列 / 表单字段 / 明细行字段）+ 附加展示要求 | 表单字段（双星） |

**主键与关联**：复合键「页面ID + 字段名 + 显示位置」。**不能用字段名做全局判重**——同名字段在不同位置是多条。

**生成链**：字段全量 JSON（抽取产出）→ 源 JSON 的「03_字段清单」→ 规格 JSON 的 fields 数组 → Excel sheet → 原型的页面字段集与明细行列集。

**自检清单**

- 每行的页面ID 都存在于页面清单。
- 显示位置的首段必须落在四种位置之内；带星号等附加信息时用括号跟在位置后面。
- 枚举字段的规则列必须能**回溯**：把取值拆开后，每个取值都能在来源系统的界面文本里找到。
- 有控件=下拉的行，规则列必须含枚举；反之，规则列含枚举的行控件必须是下拉。
- 「数据源」列无空值（含“来源系统·页面名”或“本单录入”或“系统计算”）。
- 必填条数与来源界面的星号数量一致（抽样比对）。
- 同一页面同一位置的字段名唯一。

## 03 需求总表

**用途**：五级需求，逐条可溯源到页面与来源材料。原型只做需求里写明的功能，需求没写的功能不进原型。

| 列 | 说明 |
| --- | --- |
| 序号 | 主键，1..N 连续唯一 |
| 一级 | 业务域（订单管理 / 售后管理 / 报表统计 / 系统管理 / 登录与集成 / 数据落点） |
| 二级 | 页面 |
| 三级 | 区块（页面内的功能块） |
| 四级 / 五级 | 具体需求与验收描述 |
| 备注 | 规则摘要（口径一句话） |
| 来源ID | 外部材料编号（访谈条目 / 旧系统菜单号） |
| 页面ID / 页面名 | 关联页面清单；确无页面的写「无页面（接口/配置类）」 |

**主键与关联**：序号。页面ID 关联页面清单。

**生成链**：需求材料 → 源 JSON 的「01_需求总表」→ 规格 JSON 的 requirements 数组 → Excel sheet；下游的五级需求分解文档再由规格 JSON 生成（不手改）。

**自检清单**

- 序号集合 == 1..N（连续、唯一、无跳号）。**需求改动后必须整体重排**，不能沿用旧号。
- 每行的页面ID 要么在页面清单里，要么是「无页面」；「无页面」的必须有落点说明文档。
- 每个页面至少 1 条需求（除登录/无页面项）；反之无孤立页面。
- 一级取值只出现在业务域白名单里；二级取值都出现在页面清单的页面名里。
- 旧口径词在整表里为 0（否定句白名单除外）。

## 04 权限矩阵

**用途**：页面 × 角色 的可访问级别，驱动菜单可见性、路由拦截与页面只读状态。

| 列 | 说明 |
| --- | --- |
| 页面ID | 外键 |
| 页面 | 页面名 + 优先级（便于人读） |
| 角色列 × N | 每格只能是三种值之一：全量可操作 / 只读 / 无入口 |
| 可访问角色数 | 非「无入口」的角色数（反算校验用） |

**主键与关联**：页面ID。角色列的顺序即角色数组的顺序，生成权限文件时靠它对齐。

**生成链**：权限决议 → 源 JSON 的「04_权限矩阵」→ 规格 JSON 的 permissions（每行转成 页面ID + 角色到级别的映射）→ 权限文件（由矩阵生成，勿手改）。

**自检清单**

- 行数 == 页面清单行数；每个页面ID 恰好一行。
- **每格都有值，不允许留空**；取值为三值之一。
- 可访问角色数 == 该行非「无入口」格数。
- 空白格不能靠“默认可访问”兜底：权限文件里查不到页面时按最严处理，路由守卫拦到「无权限」页而不是白屏。
- 管理后台类页面只有管理层有入口。

## 05 交互与状态

**用途**：页面之间怎么走、哪些动作用弹窗、哪些支持批量、口径类规则有哪些、四态怎么显示。原型审计按这张表逐条判实现。

| 列 | 说明 |
| --- | --- |
| 类型 | 跳转 / 弹窗 / 批量 / 规则 / 四态 |
| 编号 | 主键，按类型分段（J 跳转、D 弹窗、B 批量、R 规则、S 四态 之类） |
| 对象 | 「来源页 → 目标页」或动作名；用页面名书写 |
| 说明 | 触发条件与行为 |
| 规则 | 约束（例：返回时保持筛选与页码） |

**主键与关联**：编号。对象里的页面名要能解析回页面ID（解析不到的进人工确认清单）。

**生成链**：交互决议 → 源 JSON 的「05_交互与状态」→ 规格 JSON 的 interactions 数组 → Excel sheet → 原型审计脚本的判定表。

**自检清单**

- 编号唯一；编号在同一类型内连续。
- 对象里出现的页面名都能在页面清单里找到（或明确标注为组件/外部系统）。
- 跳转与弹窗必须有承接页面：审计脚本按「编号 → 承接页面」显式映射判定，不用模糊匹配。
- 四态条目要覆盖“每个列表/详情页都有加载、空、失败、无权限”这一主张；审计脚本断言覆盖率。
- 规则类条目里不含具体的界面文案（界面文案属于原型，口径属于需求文档）。

## 06 数据字典

**用途**：枚举与实体约束的唯一定义，取值**原样来自来源系统**；字段清单里的枚举字段指向这里。

| 列 | 说明 |
| --- | --- |
| 实体 | 来源系统的单据/报表原文名 |
| 字段 | 枚举字段名 |
| 类型 | 枚举 / 关联 / 计算 … |
| 必填 | 是 / 空 |
| 说明 | **取值原文**（逗号分隔，不加工、不排序、不删废弃值） |
| 关联 | 取值个数或关联对象 |

**主键与关联**：实体 + 字段。字段清单里规则含枚举的字段，应能在字典里找到同名字段（找不到就说明枚举来源不可追溯）。

**生成链**：来源系统界面文本 → 抽取产物（枚举）→ 源 JSON 的「06_数据字典」→ 规格 JSON 的 dictionary 数组 → Excel sheet → 原型的下拉选项（经字段生成器）。

**自检清单**

- （实体 + 字段）唯一。
- 说明列的取值个数 == 关联列写的个数。
- **废弃值也要保留**（来源系统标记为废弃的取值照样入字典），只在下游展示时按来源系统的处置方式处理。
- 枚举字段在字段清单里的取值与字典完全一致（同一字段两处出现时逐字对比）。
- 字典里的取值不得出现来源系统里没有的新造项。

## 生成链（一条线，一份投影逻辑）

    材料（抽取产物 + 访谈 + 决议）
      └─ 源 JSON（六表，无表头行，首行即数据）      ← 唯一源，只改这里
           ├─ 生成器 A → 规格 JSON（meta + 六个数组）
           ├─ 生成器 B → Excel（六张表 + 说明页）
           └─ 自检脚本 → 自检报告（生成物与源逐表对齐 + 口径关键词）

三条铁规：

1. **投影逻辑只有一份**。生成入口只补 meta（版本/日期/变更说明/真实计数），不重复实现投影，更不手写 JSON 内容。
2. **幂等**：连跑两遍，源与规格 JSON 的哈希不变（Excel 的二进制哈希会随时间戳变，用自检脚本校验内容）。
3. **产物文件头写清**：源路径 + 重新生成命令 + 生成日期 + 「勿手改」。

## 自检清单（汇总）

| # | 检查项 | 判定 |
| --- | --- | --- |
| 1 | 每张表表头列数 == 每行单元格数 | 相等 |
| 2 | 需求序号连续唯一（1..N） | 集合相等 |
| 3 | 规格 JSON 六数组条数 == 源表行数 | 逐表相等 |
| 4 | Excel 行列数与表头 == 源 | 逐表相等 |
| 5 | 枚举可追溯（字段规则里的取值能在字典/来源文本里找到） | 0 例外 |
| 6 | 页面引用完整（字段/权限/需求/交互里的页面ID 都在页面清单） | 0 例外 |
| 7 | 权限行覆盖（每页一行、无空格、取值为三值之一） | 0 空格 |
| 8 | 需求归属（每条挂页面或显式「无页面」；无孤立页面） | 0 例外 |
| 9 | 旧口径词为 0（否定句白名单除外） | 计数 0 |
| 10 | 说明页含版本号与本轮变更说明 | 命中 |
| 11 | 幂等（连跑两遍哈希一致） | 一致 |
