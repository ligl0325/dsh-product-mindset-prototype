# 工作流：五步把老系统界面变成多页原型

> **解决什么问题**：把「客户有老系统、要出一套可点的新系统后台原型」这类活，拆成固定五步。每步都给出输入、动作、产出物与完成判据。**顺序不能反**——先写页面后补规格，字段名一定对不上，最后全部返工。

## 总览

| 步骤 | 核心输入 | 关键动作 | 产出物 | 完成判据（不满足不许进下一步） |
| --- | --- | --- | --- | --- |
| ① 抽字段 | 老系统界面（截图 / 复制的界面文本 / 可访问页面） | 按位置分区、按（字段名+位置）去重、拆并格、清杂质、抓枚举与必填 | 字段全量 JSON（按页面名分组）+ 抽取报告 | 抽 10 条人工核对与界面逐字一致；无杂质项；枚举与界面一致 |
| ② 建规格 | 字段全量 + 需求材料（访谈、旧文档、接口清单） | 落六表：页面 / 字段 / 需求 / 权限 / 交互 / 字典 | 源 JSON（六表）→ 规格 JSON → Excel + 自检报告 | 自检脚本 exit 0：序号连续唯一、枚举可追溯、页面引用完整、权限无空格、旧口径词为 0 |
| ③ 生成字段 | 规格 JSON + 字段全量 | 类型/对齐/宽度推断、来源三类标注、表单分组、明细行列集 | 页面字段集 + 明细行列集 + 生成日志 | 每页 query/table/form/line 条数与规格一致；连跑两遍产物一致（幂等） |
| ④ 建原型 | 生成物 + 三页面模板 + 四通用组件 | 列表 / 详情 / 建单三模板；路由、菜单、权限由规格生成 | 可运行前端工程（含路由、权限、mock） | 对账脚本 0 真缺；路由可达；四态齐；逐屏截图看过 |
| ⑤ 验收 | 规格 + 原型 + 各脚本输出 | 自检 + 对账 + 审计 + 截图，逐条过 | 自检报告 / 对账报告 / 巡检报告 / 截图 | 全部脚本 exit 0；截图人工 review；旧口径词断言为 0 |

一句话记忆：**抽字段 → 建规格 → 生成字段 → 建原型 → 验收**。第 ①②步是源头，第 ③④⑤步全部可以重跑。

---

## 步骤 ① 抽字段

**输入**
- 老系统每个相关页面的界面文本或截图（列表页、查询区、新增/详情表单、明细行区各一份）。
- 该页在老系统里的菜单名（**它就是后续字段的归属页名，改名会让追溯断掉**）。

**动作**
1. 按四种位置分区：查询条件 / 列表列 / 表单字段 / 明细行字段。
2. 去重键用 **（字段名 + 位置）**，不是只用字段名。
3. 拆并格：老系统把多个列粘在一格，按空格拆开。
4. 清杂质：把「值」和「提示语」从字段列表里剔掉。
5. 抓枚举：字段名下一行的逗号列表，作为该字段的取值，同时该行不再当字段。
6. 抓必填：字段名前缀的 `*` / `**` 原样记录。

**产出物**
- 字段全量 JSON：`{ "<老系统页面名>": [ { "field": "...", "pos": "查询条件|列表列|表单字段|明细行字段", "enums": "逗号分隔或空", "star": "*|**|空" } ] }`。
- 抽取报告：每页四种位置的条数、被剔除的杂质清单、被拆开的并格清单。

**完成判据**
- 随机抽 10 个字段（含 1 个枚举字段、1 个必填字段、1 个并格拆出来的字段）与界面逐字比对，全部一致。
- 杂质清单里的每一条都能说出"为什么它不是字段"。
- 同一页面同一位置的字段名不重复。

细则（去重键、并格拆分、杂质黑名单、枚举与必填的识别正则）见 [field-extraction.md](field-extraction.md)。

## 步骤 ② 建规格

**输入**
- 步骤 ① 的字段全量 JSON。
- 需求材料：访谈记录、老系统的接口/对接清单、业务口径决策（尤其"起单锚点"与"履约状态谁派生"）。

**动作**
1. 先把**菜单结构**定死：一个菜单项 = 一类单据（含它的明细表与报表视图）。定不下来的话，字段没有归属页。
2. 落六表：页面清单 / 字段清单 / 需求总表 / 权限矩阵 / 交互与状态 / 数据字典。
3. 字段行的「数据源」列必须能指回来源页面（例：`老系统·<页面名>`），指不回来的字段删掉。
4. 需求层级定为 **业务域 → 页面 → 区块 →（四级/五级）具体需求**，每条需求挂一个页面 ID；确实无页面的（接口/配置类）显式标注。
5. 权限矩阵按「页面 × 角色」填满，**留空是不允许的**：无入口要显式写"无"。

**产出物**
- 源 JSON（六张表，**无表头行，首行即数据**）。
- 规格 JSON：`meta + requirements / pages / fields / permissions / interactions / dictionary` 六个数组。
- Excel（每表一个 sheet + 说明页）、自检报告。

**完成判据**
- 自检脚本全部通过、0 项未通过（判据清单见 [spec-schema.md](spec-schema.md)）。
- 生成链幂等：连跑两遍，源与规格 JSON 的哈希不变。
- 「旧口径词为 0」断言通过（口径改过的项目必须有这一条）。

## 步骤 ③ 生成字段

**输入**
- 规格 JSON（页面清单 + 字段清单）。
- 字段全量 JSON（原始录入顺序、枚举、来源页面）。

**动作**
1. 逐页取字段，按「显示位置」切成四组：查询条件 / 列表列 / 表单字段 / 明细行字段。
2. 推断类型 → 对齐 → 宽度：日期 → `date`/居中；金额类 → `money`/右对齐；数量折扣类 → `number`/右对齐；枚举 → `enum`；其余 `text`/左对齐。
3. 标注来源三类：外部引用 / 本单录入 / 系统计算（按字段名单判定，名单写在生成器里，一目了然）。
4. 表单字段按业务分组（例：客户与合同 / 项目与方案 / 金额与折扣 / 物流与收货 / 状态与其他），并按老系统录入顺序分段。
5. 明细行按**单据类型分别生成列集**（不要把不同单据的列混成一套）。
6. 生成物文件头写「自动生成，勿手改 + 源路径 + 重新生成命令 + 日期」。

**产出物**
- 页面字段集文件（每页含 query / table / form / line / required / blocks / sections）。
- 明细行列集文件（每种单据一套 columns + defaultVisible + locked）。
- 生成日志：每页四类条数、每套列集的列数与默认可见数（进对账用的数字）。

**完成判据**
- 生成日志里每页的 query/table/form 条数与规格字段清单按页统计的值一致；不一致就是过滤条件写错了。
- 明细行列集的列数 = 该单据在老系统里的明细行字段数（含并格拆开后的数量）。
- 连跑两遍，生成物内容一致。

## 步骤 ④ 建原型

**输入**
- 步骤 ③ 的生成物。
- 三页面模板（列表 / 详情 / 建单）与四通用组件（查询条 / 表单块 / 可配置表格 / 列配置抽屉）。
- 菜单结构、权限矩阵、路由模板（也在规格里）。

**动作**
1. **路由与菜单由规格生成**：菜单只放全局台账/看板/配置；单据级操作挂在锚点对象的上下文路由下（例：`/orders/:id/xxx`），从台账或详情进入。单子项分组平铺成一级链接。
2. **权限由矩阵生成**，路由守卫拦截无入口的页面到"无权限"说明页，而不是白屏。
3. 列表页：查询条 + 快捷视图 + 铺满的表格 + 分页 + 列配置；详情页：**独立路由页面**，几十个字段按区块/页签组织，不塞弹窗；建单页：按老系统录入顺序分段 + 明细行表格 + 列配置。
4. 字段渲染只读性由步骤 ③ 的 `src` 决定：外部引用默认只读，系统计算永远只读。
5. 每个页面套统一四态容器，并提供顶栏状态切换用于验收。
6. 原型文案只写操作提示、校验反馈、空态、实时计算结果与短指标标签；**不写业务规则**（见 [conventions.md](conventions.md)）。

**产出物**
- 可运行的前端工程：页面、路由、菜单、权限、mock 数据、四态。

**完成判据**
- 对账脚本：规格字段在页面源码里能找到对应写法（0 真缺；"待判定"逐条人工确认）。
- 审计脚本：四态覆盖、弹窗/批量/跳转落实、无手写字段清单。
- 每个菜单项点得开、详情页可刷新可直达（URL 带上 ID）。
- 逐屏截图走一遍（见步骤 ⑤）。

---

## 步骤 ⑤ 验收

**输入**
- 全部规格、全部生成物、全部原型页面。

**动作**
1. 跑规格自检（六表与生成物对齐 + 旧口径词断言）。
2. 跑规格 → 实现对账（字段级），真缺的按页列出来。
3. 跑原型审计（四态 / 交互 / 权限），输出巡检报告。
4. 逐屏截图：每个菜单项 + 每个详情页 + 每个弹窗；600～1400 宽度各一张，看铺满与换行。
5. 人工过一遍截图：空态是否给引导、金额是否右对齐、长字段名是否截断、列太多是否横向滚动。

**产出物**
- 自检报告、对账报告、巡检报告、截图归档。

**完成判据**
- 三个脚本 exit 0（对账脚本的"待判定"必须清零或转成别名表）。
- 截图清单与菜单项一一对应，无遗漏、无白屏。
- 旧口径词在**文档与原型源码**里都为 0（否定句白名单除外）。

## 改一处，从哪一步重跑

| 改了什么 | 从哪步重跑 | 说明 |
| --- | --- | --- |
| 老系统界面新增/改字段 | ① → ② → ③ → ④ → ⑤ | 源头变了，六表与生成物全部受影响 |
| 口径、状态名、字段叫法 | ② → ③ → ④ → ⑤ | 先改源 JSON，再重跑；最后跑旧口径词断言 |
| 菜单分组、页面归属、路由 | ② → ④ → ⑤ | 字段生成物受页面 ID 影响，稳妥起见也重跑 ③ |
| 权限矩阵 | ② → ④ → ⑤ | 权限文件由矩阵生成 |
| 页面布局、组件样式 | ④ → ⑤ | 不碰字段来源；改完仍要跑对账 |
| 只改文案（提示语） | ④ → ⑤ | 注意别把业务规则写进页面 |

## 谁做什么

| 角色 | 主要产出 | 不该做 |
| --- | --- | --- |
| 需求/产品 | 菜单结构、锚点决策、需求五级、口径词表 | 不直接改生成物 |
| 字段工程 | 抽取规则、字段全量 JSON、来源三类名单 | 不手工修字段名拼写 |
| 前端 | 三模板 + 四组件 + 页面装配 | 不手写字段清单，不手写权限表 |

## 最容易卡住的四处

1. **菜单没定就开始抽字段** → 字段没有归属页，抽完还得重来。
2. **只用字段名去重** → 跨位置的同名字段被吞掉，列表页少列。见 [pitfalls.md](pitfalls.md)。
3. **改产物不改源** → 下次重跑全部回退。
4. **原型里写业务规则** → 口径一改，原型变成错误信息源。
