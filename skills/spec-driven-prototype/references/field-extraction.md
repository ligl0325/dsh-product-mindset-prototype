# 老系统界面字段抽取规则

> **解决什么问题**：老系统界面上的字段不会自己变成一张干净的字段表——它混着并格、值、提示语、错别字和排序标记。这份文件给出直接照做的抽取规则，保证**一个字都不改、一条都不漏**。

抽取的产出要满足两条硬指标：**逐字一致**（含错别字）与**位置可追溯**（每个字段属于查询条件 / 列表列 / 表单字段 / 明细行字段哪一类）。

---

## 一、位置四分（先分区，再抽字段）

同一份界面文本里，四种位置的字段混在一起。先按界面结构分区，再在各区里抽，否则会把查询条件当成列表列。

| 位置 | 界面在哪 | 文本里的起始标记 | 文本里的结束标记 |
| --- | --- | --- | --- |
| 查询条件 | 列表页顶部的筛选区 | 文件开头（默认区） | 出现「拖拽列头到这里以用它分组」 |
| 列表列 | 列表页的表头行 | 「拖拽列头到这里以用它分组」 | 「没有数据」/「没有记录」 |
| 表单字段 | 新增/详情弹窗的录入区 | 「新增弹窗」或「详细信息」 | 出现明细区标题 |
| 明细行字段 | 新增区下半段的明细表格 | 明细区标题 | 文件末尾 |

明细区标题指这些固定串：订单明细：、签单行、样品订单行、退货单行、退回明细行：、换货明细行：、销售单行：。

规则：

1. **一个页面的四种位置都要抽**；缺哪一种就回去补界面文本（列表页与新增页往往要各截一次）。
2. 明细区标题本身**不是字段**，它是分区的边界。
3. 列表列表头里带 （降序）/（升序） 排序标记的，**去掉括号部分**才是字段名。

## 二、去重键必须是（字段名 + 位置）

**只用字段名去重会丢字段。** 同一个字段名经常同时出现在多个位置：

| 字段名 | 可能同时出现的位置 | 只用名称去重的结果 |
| --- | --- | --- |
| 客户名称 | 查询条件 + 列表列 + 表单字段 | 只剩 1 条 → 列表页少一列、查询区少一项 |
| 单据日期 | 查询条件 + 列表列 + 明细行字段 | 同上 |
| 单据状态 | 查询条件 + 列表列 + 表单字段 | 同上 |

写法（伪代码）：

    正确：key = (field, pos)；命中即跳过
    错误：key = field  →  跨位置的同名字段被吞掉

**自检**：统计每个页面四种位置各自的条数，和上一次抽取结果对比；某一种位置条数突然下降，先怀疑去重键。

## 三、并格拆分

老系统导出/复制时会把**相邻几列粘成一格**，表现为一个「字段名」里含空格，且拆开后每部分都是独立语义。**这类必须拆成多列。**

| 抽出来的样子 | 拆成 | 判断依据 |
| --- | --- | --- |
| 开票型号 品牌（举例） | 开票型号、品牌 | 两个语义中心；拆开后两词在别处单独出现过 |
| 已签单数量 本次签单数 未签数量（举例） | 已签单数量、本次签单数、未签数量 | 三个并列的数量指标，不可能是同一个字段 |
| 跟单备注 打印常规备注（举例） | 跟单备注、打印常规备注 | 一个是普通备注，一个是打印用备注 |

做法：

1. 拆分表**显式维护**（老系统就那几处，不要写通用分词器——中文分词会把「开票型号」也拆坏）。
2. 拆出来的列**继承原行的位置**（在明细行区拆出来的三条都是明细行字段）。
3. 拆分后仍要再跑一次去重：拆出来的列可能在该页别的区已经存在。
4. 生成列集时按拆分后逐列生成，并保留原顺序。

## 四、杂质识别（值被当字段、提示语被当字段）

这是抽字段最大的噪声源，分两类。

### 4.1 值被当字段

界面文本里紧跟字段名的下一行常是**值**，不是字段。

| 杂质类型 | 例子 | 识别规则 |
| --- | --- | --- |
| 日期值 | 2026-11-17 | 匹配 ^[0-9]{4}-[0-9]{2}-[0-9]{2}$ |
| 枚举取值 | 未签单（跟在「签单状态：」下） | 上一行是枚举字段 → 这行是枚举，不是字段 |
| 公司名 / 部门路径 | 广东1部、广州总部 | 出现在字段名后面、不带冒号；与已知值表匹配 |
| 单号 / 编号 | A20261113001 | 与单据号规则匹配；通常和「自动生成」同现 |
| 人名 | 张明远 | 出现在「创建人/审核人」等字段后 |

### 4.2 提示语被当字段

| 杂质 | 说明 |
| --- | --- |
| 括号里的填写说明 | 形如 （请填写完整地址）、（例：客户变更清单，需重审） |
| 操作词 | 提交、取消、保存、选择引用、上传、预览 |
| 界面固定文字 | 自动生成、无、草稿、引用、附件、打印次数、汇总:、没有数据、没有记录！、页、首页 上一页 下一页 尾页 转到 |
| 分区标题 | 基础信息系统信息、详细信息、新增弹窗、拖拽列头到这里以用它分组 |
| 分隔词 | 至（日期区间）、序（行号列头） |

**统一封成黑名单 + 三条正则**，抽取时先过滤再收字段。剔除条件（满足任一即丢）：

1. 在 NOISE 黑名单里
2. 长度小于 2
3. 命中纯日期正则 ^[0-9]{4}-[0-9]{2}-[0-9]{2}$
4. 以「（」开头且含 请 / 例 / 如 / 说明

> 注意：单据日期、客户名称 这类**是字段**，别和它们的**值**搞混。黑名单只放固定文字，不放字段名。

## 五、枚举识别

**规则**：字段名行（含尾部冒号）的下一行如果是**逗号分隔的取值列表**，那么：

- 该字段是枚举字段，控件记为「下拉」；
- 列表内容原样存进该字段的规则位（记为 枚举：值1,值2,...）；
- **这一行不再作为字段**收取。

识别条件（四个必须同时满足，防止把别的行误吞）：

| 条件 | 说明 |
| --- | --- |
| 含半角逗号 | 枚举用半角逗号分隔 |
| 不以冒号结尾 | 以冒号结尾的还是字段名 |
| 不含制表符 | 表格行不是枚举 |
| 长度小于 200 | 太长的一定不是枚举 |

例（举例）：签单状态： 下一行是 12 个取值，抽成 1 个枚举字段 + 12 个取值；单据状态： 下一行 3 个取值。

**易错点**：枚举值本身可能像字段名（如是、否、草稿）。因为它们已被枚举行吸收，不要再单独收；若同一段文字在别处也出现，按位置分别判断。

## 六、必填标记

老系统用星号前缀表示必填，**数量照抄**：

| 界面写法 | 含义 | 记录为 |
| --- | --- | --- |
| *客户名称： | 必填 | required = 是，star = 单星 |
| **合同编号： | 必填（更强约束，通常是主键类/对外单据号） | required = 是，star = 双星 |
| 客户名称： | 非必填 | required 留空 |

规则：

1. 星号**从字段名里剥掉**，但要在字段表里保留一列记录星号数量（单星与双星语义不同，删了信息就没了）。
2. 展示时用「表单字段（单星）/（双星）」把星号带在显示位置上，方便回溯。
3. **不要在原型里自行改必填**——必填来自老系统，是数据质量的底线。

## 七、保留原系统错别字

**照抄，不修正。** 老系统的错字是接口映射的匹配键，改了就对不上。

| 老系统写法（原样保留） | 常规写法 | 位置（举例） |
| --- | --- | --- |
| 竟标价、对比竟标价、竟标价合计 | 竞标价 | 订单明细行、换货明细行 |
| 己出货数量 | 已出货数量 | 样品订单行 |
| 识别咧 | 识别列 | 换货单退回明细行 |
| 客户承若返货时间 | 承诺 | 退货单、换货单 |

做法：

1. 字段名一律用原文，**抽取脚本不跑拼写检查、不做同义词归一**。
2. 需要给业务看正确写法时，另开一列「建议写法」**旁边标注**，绝不覆盖字段名列。
3. 接口映射、数据字典、mock 数据都按老系统原文写，否则取值取不到。
4. **同一概念在老系统里有两种写法时（已出货数量 / 己出货数量），两条都保留**，不要合并——合并之后你不知道哪个页面该用哪个。

## 八、其它清洗规则

| 现象 | 处理 |
| --- | --- |
| 字段名尾部有冒号 | 去掉冒号（客户名称： → 客户名称） |
| 全角/半角空格混用 | 去首尾空白；**内部仍有空格 → 视为并格信号**，回第三节拆 |
| 字段名里有排版空格（引 用） | 去掉字内空格 → 引用 |
| 列表列带 （降序） | 去掉括号 → 单据日期 |
| 同名但大小写/全角不同 | 不合并，按原文两条保留，人工确认后写进抽取报告的「疑似重复」清单 |

## 九、可直接照做的清单

1. [ ] 收集每个页面的四段界面文本：查询区、列表表头、新增/详情表单、明细行区。
2. [ ] 用「拖拽列头到这里以用它分组」「没有数据」「新增弹窗/详细信息」、明细区标题切成四段。
3. [ ] 每段内用各自的字段行规则收字段（查询区/表单区以「字段名+冒号」收；列表区以整行收；明细区以无冒号短行收）。
4. [ ] 去重键用（字段名 + 位置）。
5. [ ] 拆并格：按显式拆分表把带空格的多语义词组拆开，继承位置，再跑一次去重。
6. [ ] 抓枚举：字段名下一行是逗号列表 → 存枚举 + 吃掉该行。
7. [ ] 抓必填：剥掉星号，但记录星号数量。
8. [ ] 过黑名单 + 三条正则，剔掉值与提示语。
9. [ ] 保留错别字；不合并同一概念的两种写法。
10. [ ] 统一清洗：去尾冒号、去字内排版空格、去排序括号。
11. [ ] 输出字段全量 JSON（按老系统页面名分组）。
12. [ ] 自检：每页四位置条数、同名同位置唯一、无长度小于 2、无纯日期、枚举字段控件=下拉、必填条数与界面一致。
13. [ ] 随机抽 10 条与界面逐字比对，签一个字。

## 十、产出结构

    {
      "<老系统页面名>": [
        { "field": "客户名称",   "pos": "查询条件",   "enums": "", "star": "" },
        { "field": "单据状态",   "pos": "查询条件",   "enums": "草稿,审核中,审核通过", "star": "" },
        { "field": "客户名称",   "pos": "列表列",     "enums": "", "star": "" },
        { "field": "合同编号",   "pos": "表单字段",   "enums": "", "star": "**" },
        { "field": "开票型号",   "pos": "明细行字段", "enums": "", "star": "" },
        { "field": "品牌",       "pos": "明细行字段", "enums": "", "star": "" }
      ]
    }

字段名统一不带星号与冒号；星号单独记在 star 里。这个结构是 [spec-schema.md](spec-schema.md) 里「字段清单」的直接输入，也是 [line-config.md](line-config.md) 里明细行列集的直接输入。

## 常见坑

- 只用字段名去重 → 丢跨位置字段；见 [pitfalls.md](pitfalls.md)。
- 把值当字段（公司名 / 日期 / 枚举值）、把提示语当字段（「至」「提交」「自动生成」）。
- 顺手修正错别字，接口取不到值。
- 用通用中文分词器拆并格，把正常字段名拆坏。**用显式拆分表。**
- 抽取脚本每次重跑都往字段表里追加，条数只增不减——抽取必须是「重建」，不是「追加」。
- 抽取规则与规格字段清单的对应关系见 [spec-schema.md](spec-schema.md)；四条高频翻车见 [conventions.md](conventions.md)。
