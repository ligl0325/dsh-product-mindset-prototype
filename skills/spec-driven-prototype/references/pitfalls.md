# 真实陷阱清单（现象 → 根因 → 处置）

> **解决什么问题**：这些都是同类项目里真发生过的坑。出问题时先来这里对号，别从头猜。每条给出现象、根因与处置，处置尽量是可以直接做的动作。

## 速查表

| --- | --- | --- |

## 1. 生成器判重键失效，导致每次重跑重复追加数据

**现象**：生成脚本重跑一次，规格 JSON / Excel 的条数就多几条；同一页面、同一条需求或字典项出现两遍。跑三次就有三份。

**根因**：判重用的键和实际写入的键不是一个。典型写法是「用某个页面ID 去查重，命中就跳过」，但那条数据**已经被并入别的页面**（没有以该页面ID 落库），于是永远查不到 → 每次生成都追加一条。另一个同源问题：判重只用唯一键的一部分（例：只比 `页面` 不比 `编号`）。

**处置**：

1. 判重键必须**与写入时能反查到的键一致**（写进去什么，就按什么查）。
2. 生成后加断言：条数不减不增（跑两遍比哈希/集合）；跑第二遍输出应当全是「跳过」。
3. 追加逻辑前面打一行日志（新增 N / 跳过 M），异常时一眼看出来。
4. 已经污染的数据：删掉重复项后重排序号，再重跑一次验证幂等。

## 2. 抽取去重键用名称，丢字段

**现象**：列表页比老系统少几列；查询区少几个筛选项。字段全量 JSON 里明明有这个名字，但位置不对。

**根因**：去重只用字段名。同一个字段名（客户名称、单据日期、单据状态）常在查询条件、列表列、表单字段里各出现一次，只留第一条就把其它位置丢了。

**处置**：

1. 去重键改成（字段名 + 位置），见 [field-extraction.md](field-extraction.md)。
2. 抽取报告里输出每页四种位置的条数，与上一次对比；某类条数莫名下降，先看这里。
3. 规格字段清单的主键写成复合键（页面ID + 字段名 + 显示位置），从数据模型上就杜绝用一个名字判重。

## 3. 老系统的并格与杂质字段

**现象**：抽出来的「字段」里有 公司名、部门路径、日期、枚举取值、「至」、「提交」、「自动生成」；还有带空格的怪字段（例：「开票型号 品牌」）。

**根因**：老系统导出/复制界面文本时把相邻几列粘成一格（并格）；同时界面上的**值**和**提示语**也被逐行收成了字段。

**处置**：

1. 并格按**显式拆分表**拆（例：「开票型号 品牌」→ 两条；「已签单数量 本次签单数 未签数量」→ 三条），拆出来的列继承原位置，再跑一次去重。不要用通用中文分词器（会把正常字段名拆坏）。
2. 杂质用**黑名单 + 三条正则**过滤：纯日期、长度小于 2、以「（」开头含 请/例/如/说明；再把界面固定文字（自动生成、无、草稿、没有数据、汇总: 等）封进黑名单。
3. 随机抽 10 条与界面逐字比对——这一步必须人做，脚本没法判断语义。

## 4. 变量在使用之后声明（TDZ）

**现象**：页面白屏或半屏不出来，控制台报「不能在初始化之前访问某变量」（TDZ）。功能逻辑本身没错。

**根因**：派生数据（计算属性）里引用了下面几行才声明的变量。因为计算属性声明时会立即收集依赖，此时被引用变量还在暂时性死区。

**处置**：

1. 按固定顺序声明：**原始数据 → 派生数据 → 行为函数 → 生命周期**。
2. 需要跨引用时把被引用项改成函数声明（可提升），或把声明上移。
3. 出这类问题**一定要看控制台报错行号**，不要只截图看白屏；并修完立刻刷新确认。

## 5. mock 的 switch 用逗号导致解析错误

**现象**：构建或启动直接报语法错误，行号落在 mock 数据文件里；编辑器可能只是黄色波浪线，不影响你继续写。

**根因**：批量生成 mock 的取值逻辑时，分支用了逗号收尾（把连续的 return 写成了逗号表达式/续行），解析器读到下一个关键字就报错。批量替换、脚本生成 mock 时尤其容易。

**处置**：

1. 分支与语句用**分号或换行**收尾，不要用逗号。
2. mock 文件改完**跑一次构建**（不是只看编辑器高亮）。
3. 用脚本批量生成 mock 时，生成后立刻跑构建作为门禁：不通过就不提交。

## 6. hash 路由改 hash 不重载 store

**现象**：用脚本改地址栏 hash（或从外面点深链）切页面、换角色，页面数据不变，像是被缓存了；换个角色菜单还停在原来的。

**根因**：hash 变化不会触发整页刷新，状态层（Pinia）仍在内存里，角色/登录态还是旧的。而登录态又被持久化在 localStorage，直接整页刷新会因为没注入登录态被路由守卫踢回登录页。

**处置**：

1. 脚本验证时：**先把登录态写进 localStorage（token、账号、姓名、角色），再整页刷新**。顺序不能反，反了就是跳登录页。
2. 要在应用内换角色，调用状态层的方法（例：切换角色 action），不要改 hash。
3. 路由守卫读到的是状态层的当前值，所以任何「伪造身份」的自动化脚本都必须走上面两步。

## 7. 单页分组平铺显示分组名导致名实不符

**现象**：菜单里出现一个分组标题，下面只有一个子项，点不开或点了没反应；或者面包屑显示「首页 > 首页」。

**根因**：菜单由「分组 → 子项」模板渲染，当某分组只有 1 个子项时，仍然渲染成分组标题 + 子项，层级多余且交互奇怪。

**处置**：

1. 生成菜单时对每个分组计算 flat = （子项数 == 1）；flat 的分组**平铺成一级链接**，不渲染分组标题。
2. 生成器里加断言：分组数与子项数打印出来，人工过一眼。
3. 顺手检查「无菜单归属」的页面是否都有进入路径，避免死页面。

## 8. 静态路由 /x/new 与 /x/:id 的优先级

**现象**：点「新建」跳到了详情页，页面显示找不到该单据（因为动态段把 `new` 当成了 ID）。

**根因**：路由注册顺序里动态段（/x/:id）在静态段（/x/new）之前，先匹配上就赢了。

**处置**：

1. **静态路径路由放在动态段路由之前**注册。
2. 或改用不会与 ID 冲突的段名（例：/x/create），从命名上避免。
3. 加冒烟断言：每个静态子路径点一次，确认命中的是自己的组件（自动化里就是逐个访问路径比对标题）。

## 9. 平台差异：别用 node 直接跑前端模块

**现象**：用 `node -e` / `node file.mjs` 去 import 前端模块时报错（找不到模块、不认路径别名、不认 `.vue` 后缀、`import.meta.glob` 不存在），但浏览器里完全正常。

**根因**：node 不解析打包器的路径别名与 `.vue` 单文件组件，也没有 `import.meta.glob` 这类打包器能力。前端模块本来就不是给裸 node 跑的。

**处置**：

1. **前端行为一律用浏览器验证**：起开发服务器，按页面打开、看控制台、截图。
2. node 只用来跑生成/自检脚本（纯 JSON 与文本处理），这类脚本不要 import 前端源码。
3. 如果确实要在 node 里做字段级检查，就把检查对象限定为「源码文本 + 规格 JSON」，按字符串匹配，不要 import。

## 10. 改一份文件时误伤整份

**现象**：只想改一处，结果整个文件被重写：格式全变、部分内容丢失、行尾/编码变了，diff 一片红。

**根因**：用「整文件读 → 改 → 整文件写」的方式，叠加自动格式化或编码差异（BOM、换行符），把无关内容一起改了。

**处置**：

1. 改之前**先备份**（复制一份带日期后缀）。
2. **按块替换**：用目标字符串做锚点，只替换命中片段；不要整体重写大文件。
3. 改完看 diff 的**行数变化**：只该增删你预期的行数，多出来就是误伤。
4. 生成物与手写文档分开处理：生成物只通过脚本重生成，不手工编辑。

## 11. 需求序号重号

**现象**：需求总表里出现两个相同序号（例：两个 154），后续引用编号时指向不明。

**根因**：新增需求时沿用了旧序号（或从旧表复制过来），没有整体重排。

**处置**：

1. 需求改动后**整体重排 1..N**，不接受局部插号。
2. 自检断言：序号集合 == 1..N 且唯一。
3. 旧编号的引用（文档、落地表）改成按「页面ID + 需求名」引用，避免序号变动导致链接失效。

## 12. 只改产物不改源（重跑即丢）

**现象**：这次改好了，下一次重跑生成链，改动消失；或者两个产物之间开始不一致。

**根因**：改的是生成物（规格 JSON、Excel、字段集、路由、权限），而不是源 JSON。

**处置**：

1. 先确认「源是谁」：文档里写清来源文件，产物文件头写「自动生成，勿手改 + 重新生成命令」。
2. 一律改源 → 重跑生成链 → 跑自检。
3. 口径类改动同时更新旧口径词表，否则下次断言抓不到。

## 出问题时的排查顺序

| 顺序 | 查什么 | 为什么先查它 |
| --- | --- | --- |
| 1 | 控制台报错行号 | 白屏的一半是声明顺序/语法问题，报错直接指路 |
| 2 | 生成物是不是最新 | 改了源没重跑，或改了产物被覆盖，都会表现为「改了没生效」 |
| 3 | 跑自检与对账脚本 | 字段缺失、权限空格、旧口径残留会被脚本直接抓出来 |
| 4 | 才去改页面 | 上面三步排除了，问题才真的在界面层 |

## 症状 → 先查哪里

| 症状 | 先去 |
| --- | --- |
| 条数增长/重复行 | 第 1 条：判重键与幂等 |
| 少了列/少了筛选项 | 第 2、3 条：去重键与并格 |
| 白屏 | 第 4 条：TDZ 与声明顺序 |
| 启动即报错 | 第 5 条：mock 里的标点 |
| 切角色/切页不生效 | 第 6 条：hash 与状态层 |
| 菜单名实不符 | 第 7 条：单子项分组 |
| 新建进详情 | 第 8 条：路由顺序 |
| node 跑前端报错 | 第 9 条：改用浏览器 |
| 文件被整份改坏 | 第 10 条：备份 + 按块替换 |
| 序号重复 | 第 11 条：整体重排 |
| 改动会回退 | 第 12 条：改源不改产物 |
