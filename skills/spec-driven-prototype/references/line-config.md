# 明细行可配置列设计

> **解决什么问题**：一类单据的明细行动辄四五十个字段，全铺出来看不清、少铺又不够用。这份文件给出「按单据类型分别定义列集 + 列元数据 + 默认可见策略 + 交互 + 持久化」的完整做法，让明细行既能铺满又能自己配。

一句话：**列集由规格生成（不手写），每个单据一套、互不包含，用户改的只是「显示哪些列、什么顺序」。**

---

## 一、列集按单据类型分别定义，互不包含

**规则**：一种单据一套列集（key 独立）。**不同单据的列集不做包含、不做继承、不共用同名列** —— 即使两个单据都叫「数量」，它的枚举、宽度、分组、默认可见都可能不同。

| 列集 key（举例） | 单据 | 来源页面（举例） | 列数 | 默认可见 |
| --- | --- | --- | --- | --- |
| 销售订单行 | 销售订单 | 老系统·新方案销售订单 | 46 | 11 |
| 换货单行 | 换货台账（换出） | 老系统·换货单 | 由抽取决定 | 11 |
| 换货销售单行 | 换货台账（换货销售单） | 老系统·换货销售单 | 由抽取决定 | 11 |
| 样品单行 | 样品借用 | 老系统·新方案样品单 | 由抽取决定 | 11 |
| 签单行 | 财务签单 | 老系统·财务签单 | 由抽取决定 | 11 |
| 退货单行 | 退货台账 | 老系统·退货单 | 由抽取决定 | 11 |

**反例**：六种单据共用一套「明细列」。结果换货单里出现了「已签单数量」，退货单里出现「换货原因」，用户以为系统串了数据；而且谁也不敢删列，因为删了别的单据就少列。

**落地**：

- 生成器按「单据 → 来源页面 → 明细行字段」三段取列，一套 key 一条输出。
- 每套列集带自己的 label / doc / pageId / columns / defaultVisible，互不引用。
- 缺来源页面的单据直接报警（缺明细行字段说明抽取漏了或来源页没给）。

## 二、列元数据

| 字段 | 说明 | 例 |
| --- | --- | --- |
| key | 唯一标识，也是取值用的属性名；用字段原文 | 开票型号 |
| label | 表头显示名（一般等于 key；要缩短时单独给） | 开票型号 |
| type | 渲染类型：text / number / money / date / enum | money |
| width | 列宽（像素） | 116 |
| align | left / center / right | right |
| group | 分组名，用于按组快选与列表面板归组 | 价格 |
| locked | 固定列（不可取消、固定在左侧） | true |
| enums | 枚举取值（type = enum 时用于下拉/标签渲染） | 常规订单,特做订单 |
| custom | 是否用户自定义列（扩展口） | true |

**类型推断**（按字段名，生成器内置，顺序即优先级）：

| 判定 | 命中规则（正则） | type | align | 默认宽 |
| --- | --- | --- | --- | --- |
| 1 | 字段名有枚举 | enum | left | 按名长 |
| 2 | 日期 / 时间 | date | center | 112 |
| 3 | 金额类（金额/总价/成本/小计/合计/面价/工程价/竞标价/底价/报价/单价/费/利润，含来源系统错别字） | money | right | 116 |
| 4 | 数量类（数量/件数/以数结尾/折扣/以率结尾/比例/重量/材积）或金额类 | number | right | 88 |
| 5 | 以「是否/有无/可」开头，或含 状态/类型/类别/等级/方式/承担/品类 | enum | left | 按名长 |
| 6 | 其余 | text | left | 名长 ≥8 → 150；≥6 → 130；否则 108 |

**注意**：金额判定的关键词表要**包含来源系统的错别字**（例：把「竟标价」也算金额）。否则那个字段会被当文本左对齐，一眼就看出不对。

## 三、默认可见列策略

默认可见列是「用户没配过时看到的样子」，要满足：**关键列必须在、总列数控制在 11 左右、覆盖各分组**。

| 步 | 动作 |
| --- | --- |
| 1 | 先放 locked 列（例：货品名称、数量）——它们不可取消，永远在默认里 |
| 2 | 按**优先级词表**补最常用的 8～10 个（例：内部型号、开票型号、品牌、单价、小计、工程价、已签单数量、已出货数量、可发货数量、备注） |
| 3 | 按**分组顺序**（基础 → 数量 → 价格 → 状态与分类 → 备注）补满，直到达到上限 |
| 4 | 上限 11 列（经验值：再宽就出现横向滚动，演示与日常作业都不方便） |

**落地**：优先级词表写在生成器里，命中的列按表内顺序插到 locked 之后；剩余位置按分组轮询补。生成日志打印每套列集的「列数 / 默认可见数」，便于回归对比。

## 四、分组

分组既是列配置面板的「按组快选」，也是列顺序的骨架。按字段名正则归组，首次出现的顺序即分组顺序。

| 组 | 命中规则（例） |
| --- | --- |
| 基础 | 货品/型号/品牌/单位/料号/编码/名称/特征/厂家/品类/类别/质保/条码 |
| 价格 | 单价/面价/工程价/竞标价/底价/报价/售价/成本/金额/小计/合计 |
| 折扣 | 折扣、以「折」结尾 |
| 数量 | 数量/件数/以「数」结尾/材积/重量/毛重 |
| 备注 | 备注/说明/政策/标准 |
| 状态与分类 | 状态/类型/类别/是否 |
| 其他 | 以上都不命中 |

规则：一个列**只进一个组**（按表顺序取第一个命中），否则按组快选会重复计数。

## 五、固定列保护

**规则**：locked 列不可取消、不可被反选掉、固定在表格左侧。

| 交互 | 对 locked 列的行为 |
| --- | --- |
| 取消全选 | 保留 locked 列 |
| 反选 | locked 列强制选中 |
| 按组取消 | 跳过 locked 列 |
| 拖拽排序 | 允许（顺序可改），但仍在左侧固定区 |
| 恢复默认 | 回到生成本身给的默认可见列 |

**反例**：没有固定列保护，用户取消全选后把「货品名称」也取消了，表格变成一排数字，看不出是哪一行的什么货品。

## 六、交互

| 操作 | 行为 | 备注 |
| --- | --- | --- |
| 全选 | 把**当前搜索结果**里的列全部选中 | 搜索时全选只作用于筛出来的列，不是全部列 |
| 取消全选 | 去掉当前搜索结果里的列，locked 保留 | |
| 反选 | 当前搜索结果内反转，locked 保持选中 | |
| 按组快选 | 点组标签：该组若已全选则取消（跳过 locked），否则整组选中 | 标签上显示 已选/总数 |
| 拖拽排序 | 拖到目标列位置插入 | 顺序即显示顺序，随持久化保存 |
| 搜索 | 按 label 或 key 包含匹配，实时过滤列表 | 不改变选中状态 |
| 恢复默认 | 交由父组件把可见列重置为 defaultVisible | 不要在这里自己猜默认值 |
| 计数 | 面板顶部显示「已显示 n / 总列数」 | 表格工具条上也显示一份 |

**排序细节**：拖拽后要按「列集定义的顺序 + 自定义列」归一化一次，避免出现定义外的顺序导致下次读取错位。

## 七、持久化

**规则**：按列集分开存，只存「可见列 key 的顺序数组」，读的时候做校验。

| 项 | 做法 |
| --- | --- |
| key 命名 | 前缀 + 列集 key（例：前缀.明细列集.<列集key>） |
| 存什么 | 只存可见列的 key 数组（顺序即显示顺序） |
| 何时写 | 可见列变化时自动写（深度监听） |
| 何时读 | 初始化时读一次；无值 → 默认；不是数组或为空 → 默认 |
| 异常 | 读写都包 try/catch，localStorage 不可用时静默回落到默认 |
| 归一化 | 读出来的 key 按列集定义顺序排；定义里没有的 key（自定义列）附在后面 |

**反例**：所有列集共用一个 localStorage key。配了销售订单行，切到退货单行发现列也变了（因为 key 相同），用户以为系统记混了。

**列表页列配置同理但要单独一套 key**：列表列来自规格的「列表列」，明细列来自「明细行字段」，两者不要共用一个存储键。

## 八、扩展口（自定义列）

**规则**：允许业务方加列，但自定义列必须**与生成的列区分开**，并且可持久化。

| 项 | 做法 |
| --- | --- |
| 新增 | 输入列名 → 生成 key（自定义前缀 + 序号）→ type = text、group = 其他、宽 120 → 自动可见 |
| 标记 | 列对象带 custom = true，便于统计与导出时区分 |
| 保存 | 自定义列定义要与可见列一起持久化；只存可见 key 会导致刷新后自定义列丢失（只能看到 key 找不到定义） |
| 上限 | 给出上限（例：每套列集 10 个），避免无限加列拖慢渲染 |

**注意**：只把可见列写进 localStorage、自定义列定义留在内存，是**当前实现的一个缺口**——刷新后自定义列消失。改法：持久化时把自定义列定义一并存进同一个 key 的对象里（可见顺序 + 自定义定义），读取时兼容旧的纯数组格式。

## 九、自检清单

- 每套列集的 defaultVisible 都是 columns 的子集，且顺序在 columns 里能找到。
- locked 列全部出现在 defaultVisible 里。
- defaultVisible 数量在 8～11 之间。
- 每个列有 type / align / width / group；type 与 align 匹配（money、number 右对齐，date 居中）。
- 金额与数量关键词表能覆盖来源系统的错别字写法（例：以「竟」开头的价格字段）。
- 每套列集有自己的存储 key；不同列集之间的 key 不共用。
- 搜索、全选、反选、按组快选都不会把 locked 列去掉。
- 缺明细行字段的单据在生成时报警，不静默跳过。
